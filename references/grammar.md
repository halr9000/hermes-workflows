# Graph grammar and authoring boundaries

Workflow 1.3.5. Minimal form: `workflow{action:"run", graph:{"name":"check","nodes":[{"id":"a","type":"agent","goal":"Return a fenced JSON object with key ok=true"}]}}`. The run action's `name` overrides `graph.name`; otherwise the graph name is used, then `workflow`.

## Per-run concurrency (optional)

A graph may set top-level `concurrency` (simultaneous agent nodes) and `item_concurrency` (simultaneous fan-out items), positive integers only; booleans, floats, zero and strings are refused at submit with the key named. The door writes the effective values to `run.json` under those exact keys, never trusts a graph value as an owner cap. Each author value is clamped to the owner's positive-integer plugin settings `max_concurrency` / `max_item_concurrency` (`plugins.entries.hermes-workflows.settings`); absent caps default to 4 / 8, the runner's historical values. A cap below the historical default constrains a run even when its graph omits that key; malformed owner caps refuse the launch. With neither graph keys nor owner caps, neither key appears in `run.json` and the old behavior is unchanged. These scheduling limits never participate in `def_hash`/`efp`: adjusting concurrency does not un-freeze committed nodes. These values are baked into `run.json` at submit and `amend` never re-bakes them: amending a graph cannot change a live run's concurrency (a frozen-run consequence, safe — the scheduler keeps the caps the run launched with).

## Run verdict (optional)

A graph may set top-level `result: "<node id>"` to name the node whose output IS the run verdict. It must be a string naming an existing non-gate node; a missing, non-string or gate target is refused at submit with the `result` key named. Terminal means run status ∈ {`done`, `failed`, `stopped`}: terminal `status`/`wait` reads then carry `result: {node, status, output}` for that node (`output` is null when the node did not commit one); any other status (`running`, `held`, `interrupted`, …) never grows the field. The `result` target names a node id of the EXPANDED graph — a ref to an included node must use the literal `alias__<id>` form, because validation runs post-expansion where the node id is namespaced; an exported public name is refused with the `result` key named (it fails closed, it never silently resolves). A child graph's own top-level `result` is dropped on fusion like `defaults` (no child top-level key is carried) — only the parent's composite key is meaningful. The field is carried by `run_id` reads only: the compact `lane_key` status view never carries node payloads (no outputs at all), so it omits `result` even for a declaring graph. Absent key = no `result` field and unchanged status bytes; the key never enters a node fingerprint.

## Nodes and data

Graph-level `defaults:{schema, timeout, max_turns, reasoning, provider, model, context, require_route}` fills any agent key the author left unset (`defaults.context` is prepended once to each agent's own context); explicit node keys win. Agent fields: `id`, `type:"agent"`, `goal`, `after:[ids]`, `context`, `schema`, `inputs`, `model`, optional `provider` paired with a nonempty model (a literal `model:"<provider>/<id>"` with no `provider` bakes both at submit when `<provider>` is one the seat already routes through — an alias or tier target prefix, or a configured `providers:` key — so it routes like the alias for the same model; any other prefix passes through verbatim), `reasoning`, `toolsets`, `max_turns`, `timeout`, `run_budget`, `shape`, `repo`, `fanout`, the route-integrity key `require_route` (below), and the optional team fields `profile`, `requires`, and `after_partial` (below), the convoy key `order_only` (below), and the publisher capability keys `publishes` / `suite_proof` (below). `on_fail:"skip"` turns this agent's failure into the join-tolerant `skipped` terminal state (the run continues; a join with one live dep still runs; the death stays readable as `caught_error`/`caught_error_class` on the skipped record); `on_fail:"<agent-id>"` additionally lets that fallback agent run. Checked at run time: the fallback must exist, be an agent, and not be an ancestor — an invalid target logs `node.on_fail_invalid` and the failure stands. `cancelled` (stop) deaths are never caught. `shape:recon|build|review|publish` fills `max_turns`/`timeout` from measured p95 presets when unset (default shape `build`). `repo: <path>` (absolute or run-dir-relative) declares the git lane the node owns: at commit the runner checks `git status --porcelain --untracked-files=no` of that lane, and a done/partial over a lane with uncommitted TRACKED changes commits `failed` `error_class:"incomplete_work"` with `lane_dirty` porcelain instead of handing off an uncommitted fix downstream would never see (the dad50be0 false-green shape). Never an auto-commit; commit in the lane, then amend/re-run re-drives the node. At (re-)drive STARTUP the same scan gates admission: a declared lane with uncommitted TRACKED wreckage from a dead attempt refuses the run `error_class:"lane_wreckage"` before any spawn, naming the files and the banking paths (`git stash push -m redrive:<run>:<node>` in the lane, or a patch at `<run>/wip/<node>.patch`) — bank first, then re-drive (est-2ek.1.660). Untracked files never dirty a lane; git being unable to answer fails open. `echo` nodes (`{id, type:"echo", after, output}`, plus the publisher flag `publishes`; est-2ek.1.603) commit `output` verbatim with no spawn. Unknown keys (including `agent.when`) are rejected before write/spawn. The node's `schema` constrains fenced JSON: the runner appends the reply contract (required keys + types) to the prompt itself, extracts the last balanced JSON object from noisy stdout, and gives the child one correction retry — authors never write contract prose. A string field may carry `enum` (non-empty list of non-empty strings): the allowed set shows in the child's prompt, and a reply outside the set takes the same typed correction retry as a type violation (the retry names the allowed values; a second offense fails `error_class:"schema"`) — a misspelled verdict never commits. Keep work idempotent: unfinished work may replay. An explicit provider routes via the child `--provider` flag; unset model uses the seat default even for fan-out.

A string field may carry `minLength` and an array field `minItems`, each a non-negative integer (bool is never a count): the floor shows in the child's prompt, and an answer under it takes the same typed correction retry as a type violation (`minLength` counts characters after `strip()` — a whitespace-only string is under the floor; a deliberate, fail-closed deviation from JSON Schema); a second offense fails `error_class:"schema"`. The door admits each floor only on its enforceable placement (`minItems` on `type:"array"`, `minLength` on `type:"string"`), so a schema never carries a constraint the harvester cannot check.

`require_route` (bool; default TRUE on nodes that pin an explicit model, never baked when left unset): fail-closed pinned routes (#25). The door's submit ping AFFIRMATIVELY proving a pinned route dead — or answering from the fallback ladder (recorded route != pinned route) — REFUSES the launch (`route_unavailable`) instead of silently billing another model; `false` opts into the ladder explicitly. Infra-absence (core unimportable, offline host) stays `unknown` = warn-only: missing evidence never blocks. A proving-alive ping bakes the door-only `route_verified` annotation (author-supplied values are stripped at the door and dropped again at resolve — never trusted from an author, never forged through `save`; the runner's closed key set carries it so the committed `graph.json` loads) and the runner then holds the committed `served_model` to it — a contradiction commits `failed`/`route_unavailable`. `require_route`/`route_verified` never participate in a node's fingerprint (like budgets: policy/annotation, not work), so a door bake or a defaults flip cannot un-freeze committed nodes. A node's death also lands in the per-profile quota cache when classed `fatal_quota` (#24): a 429 carrying its own reset horizon fails on the first attempt — the bounded ladder can't beat a multi-day reset — and the door refuses a re-launch on that model until the horizon passes, one recovery ping first. A credential-window 429 is its own class  `ratelimit` (#54): the child's `... credentials are rate-limited for <model> ...` banner parks at ~5-minute jittered intervals (`run.json` `ratelimit_interval`/`ratelimit_jitter`, same meta-only law as `retry_backoff`). The wall is a REAL bound (wf159c): a park fires only when the worst-case jittered wait (`interval × (1 + jitter)`) plus a real respawn window (≥ 15% of the wall, floor 0.25 s) still fit inside the node's wall budget — otherwise zero parks — the deadline is rechecked after the wait, and every spawn after a park runs CLAMPED to the remaining wall (a park can never buy a fresh full timeout; #11's one-time extend still stacks). A banner death discovered AFTER a ladder respawn is handed to the same park by the transient ladder (attempts ride along) — late or early, the dispatcher contract is identical. The park's wait observes the fan-out quorum cancel: a satisfied quorum never waits out a parked straggler. Each park emits `node.retrying error_class:ratelimit backoff_s:N`, and gives up honestly with the verbatim `credential rate-limited for <model>` as the error text so a dispatcher can switch model instead of requeue. A child that exits rc=130 carrying the CLI's lease notice (`Stopped waiting for another Hermes process on this session. Your message was not processed.`) is classed `lease_busy`: another Hermes process held the session lease so the message never reached the model — a transient collision, so the node gets exactly ONE bounded re-drive as a FRESH session under the next attempt key (never a resume of the still-busy session; the harvest preamble replaces the resume preamble) after `node.retrying error_class:lease_busy`. A rc=130 death without that notice keeps the ordinary classification untouched.

`confidence_substrate` (OWNER config, not a node key — #116): the deployment's sanctioned fallback substrate for fail-closed pinned routes. Set it as `plugins.entries.hermes-workflows.settings.confidence_substrate` (or top-level `workflows: confidence_substrate:` in this profile's config.yaml; env `WF_CONFIDENCE_SUBSTRATE` overrides for one process): a `"provider/model"`, a comma list, or a list of such / `{provider, model}` mappings — the ORDER is the ladder. It is consulted ONLY on the #25 dead/surprise branch: the door pings each rung and the FIRST alive one serves — the node def is re-routed and engine-stamped `substrate_substituted` (`{from, to, reason, source}`; author-written values are stripped, the runner re-verifies the stamp against the config at commit and fails closed on a forged one), `route_verified` re-bakes to the served rung, and the node's result schema machine-gains the required `substrate_disclosure` clause (the runner stamps the honest label into the node record; the child cannot author it away or omit-fail on it). No config, no ladder, or every rung dead = today's `route_unavailable` refusal, verbatim. `require_route: false` stays a pure opt-out (no substitution is forced onto an opted-out node) and an explicit LIVE pin always beats the configured ladder. The stamp never participates in the fingerprint (annotation), but a substitution changes the node's real `model`/`provider` — the hash sees that, and so does replay-skip.

`profile` (agent only, optional): run that node AS a named teammate profile — DELEGATION, not isolation: the child runs with the TARGET profile's SOUL, memory, `.env` and tools, same UID, one owner; no isolation is claimed or possible. Node-level only (fan-out items carry no profile of their own). The door renders `{run.KEY}` in `profile` BEFORE validation, so a graph can name its teammate per launch (`"profile":"{run.reviewer}"`). Validation completes before any write/spawn: the name is a non-empty profile DIRECTORY whose `config.yaml` exists; `default` is never a target; the target's owner-written `<profile_home>/workflow_team.json` lists the LAUNCHER in its `accept_from` array ("default" is a legal launcher name). The launcher identity is read from the door's own HERMES_HOME, never from a graph arg. A target deleted between validation and spawn is a typed `error_class:"spawn"` failure (`profile gone: <name>`) — never a launcher fallback.

`requires` (agent OR gate, optional): output preconditions on ancestors — `{"<ancestor>": ["field","dotted.path",…]}`; every key must be in the node's `after` closure and every path a non-empty string, or the graph is rejected before write/spawn. At schedule time (before the spawn) each path resolves against the ancestor's committed output (done/partial): a missing OR null value makes the node `failed` with `error_class:"precondition"` (`error: precondition unmet: <ancestor>.<path>`, `output.missing` lists the paths) with ZERO spawns, and the run fails on the existing failed path (`blocked`, WORKFLOW_FAILED, downstream blocked) — a reader can never discharge an obligation on a null output. The retry ladders never see a precondition death; a resume re-evaluates it (supply the missing field via `amend` and the node spawns). 1.0.x `skipped` semantics are untouched: a graph that WANTS skip-on-missing uses the existing `when` gate + `on_skip:"prune"` path. A node without `requires` facing a null upstream spawns exactly as before.

`after_partial` (agent OR gate, optional, bool only — echo rejects it): the after-edge release law for a harvest-on-death `partial` ancestor (a child that died mid-work after printing a valid fenced answer; #4 commits its output as `partial`). Default FAIL-CLOSED: a plain `after` edge is NOT satisfied by a `partial` — at the wave boundary the descendant commits `failed` with `error_class:"precondition"` (`error: blocked_by_partial_ancestor: <nid>`, `output.missing` lists the blocking ancestors) and ZERO spawns, so verify/suite can never be silently released onto an incomplete candidate. The ancestor's harvest stays committed and readable; `partial` still counts RESOLVED, so blocked descendants always reach the typed verdict instead of deadlocking the run. Set `after_partial: true` on a descendant to consume the harvest deliberately: the edge then satisfies and the node spawns off the harvested output. The same provenance law covers `requires`: a listed path on an ancestor whose committed record carries harvest provenance is UNMET (`precondition unmet: <ancestor>.harvested`) without the opt-in, satisfied with it. Carve-outs that the law never touches (#4): a node's OWN fan-out partial-credit merge still commits `done`, and a LEAF `partial` still closes the run green with its harvested output in the summary — only the after-edge release changes.

`order_only` (agent OR gate, optional, list of ids that ALSO appear in `after` — echo rejects it): marks those after-edges as ORDERING-only, the convoy shape (lane N+1's converge waits for lane N's converge, consuming none of its output). Over an ordering edge no data flows: the predecessor's output is not auto-injected into `## Inputs` and the ancestor gate-answer walk does not cross it. The predecessor releases the edge when it is done, skipped OR `partial` (finished is finished — an ordering edge consumes no harvest). The SPLICE: when the predecessor is dead — `failed`, or pending behind a failed DATA edge so it can never run — the edge is satisfied as soon as that dead member's own `order_only` predecessors are (recursively), so no node inherits a dead lane as its predecessor and the chain order among the living holds. The released node logs `node.spliced` `{node, past:[dead ids]}` once. The dead member and its data descendants still fail the run; `run.blocked.residue` tells them (`data_dead`) apart from anything still parked only behind ordering (`order_dead`). Plain `after` (no `order_only`) keeps today's law: a dead predecessor blocks.

`publishes` (agent OR echo, optional, bool only — gate rejects it; est-2ek.1.603): declares that this node has PUBLICATION side effects (opens a PR, tags, pushes, files a release). The runner never infers side effects from prose — a goal that says 'publish' without the flag behaves like any other node; a goal that never says it still gates when the flag is set. A declared publisher is REFUSED TYPED at the wave boundary BEFORE any Popen (pre-execution, like the shelf guard; the echo commit path is covered too): `failed` `error_class:"precondition"`, `error: publisher_ungated: <nid> requires a verified suite proof token; missing proof from: <ancestors>` — the refusal names the missing proof, and the publish never executes. The gate opens only when EVERY `suite_proof`-declaring ancestor in the node's `after` closure has a valid token (a publisher with NO declared producer upstream is refused too — fail-closed). Nodes without the flag are untouched.

`suite_proof` (agent OR gate, optional, bool only — echo rejects it; est-2ek.1.603): declares a recognized suite-PROOF producer (the node runs the native suite). When it commits `done` (NOT `partial`), the runner mints the durable token `nodes/<id>.suite-proof.json` `{node, efp, fp_rule_version, written_at}` — the same efp stamp the node record carries. Verification is fail-closed: the token must name the producer, the producer's record must be a CURRENT efp-valid `done` commit, and the token efp must match — an amended producer (new efp, no re-run) never launders a publish off its stale token.

`effects` (agent OR echo, optional, list of 1–8 receipt rows — gate/join reject it; est-pygyy, issue #56): declares the postconditions a publication node's `done` rests on. Local-file rows are exactly `{file, sha256?, min_bytes?}`: `file` is a run-dir-RELATIVE path (absolute, backslash, or `..` paths are refused at the door; the runner never reads outside the run dir), `sha256` an optional 64-hex digest, `min_bytes` an optional positive int. At the commit edge — after the lane gate, before the record lands, on the agent, fan-out aggregate, and echo paths — the runner reads the bytes ITSELF: exists, non-empty, `>= min_bytes`, digest equal. Every row it proves records `{file, exists, bytes, sha256, ok:true}` into the node record's `effect_receipts`; ANY unproven row demotes the commit to `failed` `error_class:"effect_receipt"`, `error: effect_receipt_unproven: <file>: <missing|empty|N B < min_bytes M|sha256 mismatch>` — the measured facts still ride on the record, so recovery re-reads them instead of re-authoring the artifact. A proven-fail: never retried by either ladder, the run never reaches `run.done` over a false publication, and the runner NEVER fabricates an `ok` row. Honest degradation: no `effects` key = today's behavior byte-identical — no inference from prose, no graph rewrites required.

External rows are exactly `{target, expected-readback}` (non-empty strings, no local-file keys). The publication adapter supplies `output.effect_receipts:[{target, expected-readback, actual-readback, verdict}]` from its remote readback; the runner does not infer or perform remote writes. Exactly one receipt per declared target must carry `verdict:true` (boolean, never a truthy string/number) and a non-empty string `actual-readback` equal to the declaration and the receipt's expectation. Fan-out receipts are read from committed successful/partial item outputs in `all_results`. The checked rows ride in `metrics.effect_receipts` on node records and status. A false/absent/ambiguous readback blocks finalize (`run.blocked`, `effect.unreceipted` with `recovery:"publication-only"`) while the author's done/partial record and artifact remain banked; unchanged resumes re-read, never respawn the author. Complete only the outstanding publication/readback, then use `amend` to echo-bank the original committed output with its completed receipts. Nodes without effects remain byte-identical.

`after` schedules AND injects: every direct parent's committed output lands under `## Inputs` automatically (8 KB per parent, truncated with a marker). `inputs:["a", "a.key"]` picks a dotted path or a non-parent ancestor, failing loudly on missing paths; a parent named in both appears once. A gate cannot declare `inputs`, but a downstream agent can read its committed output. Fan-out uses `fanout:{"items":[...],"goal":"Audit {item}"}` or `items_from:"a.items"`; `goal` is optional when every item carries its own (the node goal then prefixes each item prompt). `{item}` is the item value; `{index}` is the zero-based item number. Dict item fields interpolate as BARE `{FIELD}` tokens (the item's key names directly — a dotted `{item.FIELD}` never resolves and ships to the child verbatim; `fmt_goal` only ever looks up bare names, and `_dangling_placeholders` warns at spawn when one survives). A dict item's nonempty `goal` overrides the template. Unreferenced keys are not injected. The `fanout` closed set is exactly `{items | items_from, goal, schema, quorum, quorum_drain_s, ledger}` — any other key is rejected with `unknown key; allowed: ["goal", "items", "items_from", "ledger", "quorum", "quorum_drain_s", "schema"]` (the message is the JSON of the sorted set — read it from the error, never a copy); `schema` is an object constraining EACH item's reply (same reply-contract rules as the node `schema`). `quorum` (optional) races: once N succeed, the rest are cancelled (`error_class:cancelled`, excluded from failure math); without it the fan-out waits for every item. `quorum_drain_s` (optional number >= 0; only legal WITH an explicit `quorum` — alone it is refused) drains instead of killing blind: at the quorum moment the runner arms ONE window of that many seconds; a straggler still running then may LAND its answer inside the window (anything that lands commits like any other item — the drain cancels nothing that arrives before the deadline), and whatever is still running at the deadline is cancelled exactly as without the key, same evidence strings. **Documented default: `0` = cancellation is immediate at the quorum moment (today's behavior).** `ledger` (optional, #85) is the item-indexed INPUT LEDGER: one row per item, positionally aligned — a `'<node_id>.<dotted.path>'` input-ref string or `{"source": "<node_id>.<dotted.path>", "artifact": {"file": rel/path, "sha256"?: 64-hex}}` naming the on-disk artifact the item consumes. At admission the door refuses the graph fail-closed unless rows map 1:1 to items: a missing row ("item N is missing ledger source"), a surplus row, two items sharing one source, or a source head outside the node's `after` ancestry each name the item and the missing/extra source; when run-dir bytes are measurable (amend, and validate given run_id) an absent artifact file or a sha256 mismatch is likewise refused. A mis-declared item can therefore never silently get another item's artifacts (the WOFS W1f evidence-loss class); graphs without a ledger declaration are byte-unchanged — no ledger, no guard. A reducer with `inputs` can aggregate; optional schema-defined feedback arrays need no new workflow action or mandatory worker boilerplate.

## Gates and branches

A gate has `type:"gate"`, `after`, optional `question`/`options`, `when`, `on_skip`, `default_option`, `hold_timeout`, and optional `requires` — gates take the same output preconditions as agents (`failed` with `error_class:"precondition"`, zero spawns; see Nodes and data). Human gates hold until release; with `hold_timeout` (s) the runner parks at zero tokens and, at expiry, releases with `default_option` (must be one of `options`; event `gate.auto_released`) or, without one, logs `gate.expired` once and keeps holding. `wait:{"wait_s":N}` is a timer; `wait:{"until_argv":["program","arg"],"every_s":60,"timeout_s":3600}` rechecks fixed argv without a shell; Inline argv is not `run_context`-rendered and surviving `{run.KEY}` refs refuse at run/amend. Library-sourced launches render argv from explicit nonempty string bindings, then refuse any survivor; no shell is involved. A machine timeout is failure, not approval. Gate options are answer DATA; a "no" response alone does not prune work.

Bounded `when` reads `out.<ancestor>.<path>`, with string/number/boolean literals (`true`, `false`, `True`, `False`), comparisons, and/or/not and parentheses. A false predicate defaults to `on_skip:"prune"`: the gate and descendants with only skipped dependencies become terminal-skipped. Explicit `on_skip:"pass"` skips the gate question but lets descendants proceed. A true predicate still holds or waits; a predicate error fails safe rather than skipping. For mutually exclusive arms, use two complementary gates, each with its agent, then a mixed join. See tested `examples/basics/approve-publish.json` and `examples/basics/branch-on-verdict.json`. A missing upstream input fails rather than injecting an empty value. There is no native vote/loop/foreach engine.

## Staleness and replay

Each new commit (including gate answers, spawn identities and runner exits) stamps its fingerprint rule. Readers recompute against the current graph under THAT recorded rule, not necessarily the reader’s default. A definition or ancestor edit invalidates the affected record; an unknown rule fails closed. Unstamped historical records replay when any known rule matches the current graph — two rules agreeing on the same hash prove the definition is unchanged, so an equal-hash pair no longer fails closed (a real definition change matches no rule and still does). A budget-only edit invalidates old-rule commits but not new-rule commits. A pre-upgrade reader already loaded in a long-lived serve process must restart after deployment.

## Top-level provenance

A graph may carry a top-level `provenance:{owner, source, saved_at, source_digest}` object (closed key set; unknown keys rejected). The door writes it into a library entry ONLY when `save` supplies `source` (≤200 chars: repo path, URL, skill) or the saving door runs under a named profile (owner = launcher profile); a default-profile save without `source` keeps the pre-1.1 bytes exactly. `source_digest` is a sha256 over the canonical `nodes` JSON — deliberately named apart from `graph_fingerprint`, whose rule-stamped meaning is unchanged. `library` rows show owner/source/source_digest only when present; `run from:<name>` stamps `run.json.graph_source = {name, owner, source, source_digest}` only when the library graph carries provenance. Provenance is attribution metadata, not an ACL: nothing reads it to allow or deny.

## Tags (meta envelope)

Library entries carry `tags` in the #50 `meta` envelope (`{meta:{description,tags}, graph}`), never inside the graph — the inner graph stays validator-clean and a `tags` key inside a bare graph remains an unknown-graph-key error. #70 extends the #50 tag law: each of the 1-10 tags is either a legacy FLAT token (library-name grammar) or a faceted `facet:value` — lowercase-normalized, dups collapsed, exactly one `:` with non-empty `[a-z0-9._-]` both sides and <=48 chars. The FACET (before the colon) is a CLOSED set — `use_case`, `repo`, `domain`, `risk`, `note` — the hard-namespace/soft-value split: values drift and a consolidate agent can mop them, but colliding facets (`intent:` vs `task:` vs `use_case:`) fragment the taxonomy on the axis routers filter on and cannot be merged safely after the fact. `note:` is the sanctioned escape hatch for freeform values nothing should filter-route on. Seed `use_case:` values (reuse before coining): `code-review`, `research`, `troubleshooting`, `triage`, `testing`, `release`, `decision`, `report`. Seed `risk:` values (reuse before coining): `low`, `high`, `breaking`, `cosmetic` — an unseeded facet is the first to drift. Retain-on-overwrite: a `save` onto an existing entry that omits `tags`/`description` carries the previous ENVELOPE's values (a bare entry's top-level `description` rides along when the incoming graph states none) — re-shelve-from-run_id must never silently drop discovery coverage; `tags: []` stays the #50 fail-closed error, so erasing tags is a deliberate file edit: a hand-edited `meta.tags: []` is the ERASED state and the retain read keys on the key's PRESENCE, not its truthiness — a later save that omits tags carries the erase forward (the empty list and the envelope both stay). A stored `meta.tags` that is not a list is an invalid shape: resaving fails closed with a repair-or-delete error, never a silent overwrite, same law as the corrupt-entry read. The corrupt-entry refusal covers the WHOLE damaged-image class (#146 item 1): a prev file that parses as JSON but is no valid image at all — ambiguous envelope+bare markers, neither shape, an empty `nodes[]` — refuses a retain-needing save with the typed reason and stays byte-untouched; an explicit save naming tags+description is the documented repair route over any damaged entry. `library` optionally filters `tags:[…]` ALL-match (queries normalize the same law; two calls to union), and a tagged library echoes `tag_vocab` (whole-library {tag: count}) on every response — reuse what you see, never coin what you don't — plus `tag_match_counts` on filtered responses so an empty result diagnoses itself (term at 0 = spelling miss; term exists but never co-occurs = sparse coverage, drop the facet). An EMPTY filtered result also carries `empty_cause` (#146 item 2): `{spelling_miss: [terms at 0 library-wide], co_occurrence_starved: bool}` — with no zero term the kill is co-occurrence itself and the hint names the rarest term to drop. The cause is promised by the FILTER, not earned by the vocabulary: an empty vocab set (empty, tagless/bare, erased-to-`[]`, or quarantined-only shelf) still owes it — every queried term simply sits at 0. A non-empty filtered response and every unfiltered call never grow the key (golden-bytes law). A tagless library keeps the pre-#70 bytes exactly (golden law). Deliberately unbuilt, each with a trigger: did-you-mean at save (an observed bad save), patch/alias/OR-grammar (100+ entries); facet-grouped vocab fires on co-occurrence blindness, not size — flat {tag: count} cannot distinguish '5 have both' from '5 split across'; numeric companion: vocab keys > 300 fires the prune-or-consolidate wake, desktop library view (separate feature).

## Library run-context contract

`library name:<name>` and `/wf show <name>` expose refs-derived required inputs
plus the exact instantiate command. Envelope `meta.params` may describe each key
with `required`, `desc`, and a nonempty string `default`; graph refs always remain
required regardless of the metadata. Defaults are suggestions, never implicit
bindings. A malformed params block is read as absent, not entry quarantine.
`save params:{...}` writes the envelope; omission retains prior params and `{}`
clears them. Missing/dead declarations on an ENVELOPE entry yield named non-fatal
`s12` save warnings; a bare save's contract is wholly ref-derived and never warns s12.
`wfcommon.run_context_contract` is the shared predicate for these sets.

`run from:<library name>` refuses missing, empty, whitespace-only or non-string
bindings for graph refs before any state write, on ordinary and dry-run launches.
The shared render surface is goal/context/question/profile, fan-out goal and item
goals, echo string output, gate options and `wait.until_argv`. Replacement is
single-pass; values carrying surviving refs are refused, and values with braces
in fan-out templates remain refused. Inline graphs preserve their existing
leniency on ordinary text, but unbound machine argv still refuses.

## Composite graphs (include)

A graph may compose shelved library DAGs with a top-level `include` annotation:

```json
{"name": "meta",
 "include": [{"as": "rev", "use": "frontier-review",
              "seeds": {"artifact": "/abs/path"}, "exports": {"join": "review_verdict"}}],
 "nodes": [{"id": "publish", "type": "agent", "after": ["review_verdict"], "goal": "…"}]}
```

`include` is a graph-level annotation like `grammar` and `provenance`, never a node type: the node-type closed set (`agent|gate|echo`) is untouched and the runner never learns includes exist. Composition happens at MATERIALIZE time — the door expands the graph before validation, before `defaults` baking and before `{run.KEY}` binding, on each of `run`, `amend` and `save`.

Directive keys are exactly `{as, use, seeds?, exports?}`. `as` is the namespace alias: alnum start, `[A-Za-z0-9_]` only — no hyphens, no dots — ≤ 24 chars, unique per graph. (The no-hyphen rule is load-bearing, not stylistic: the alias becomes the head prefix of every generated id, and ids appear inside `when` `out.<id>.` paths, which the bounded-expression tokenizer lexes heads as `[A-Za-z0-9_.]` only — a hyphenated alias would make the `when` rewrite silently no-op. The alias grammar is deliberately a subset of the when-token head grammar, so the refusal lands at the include guard, naming the alias.) A present-but-malformed `include` — `null`, an object, an empty list — is a named refusal (`include must be a non-empty list`); only an ABSENT key means "nothing to expand". `use` is a library entry name, resolved by the same reader `run from=<name>` uses. `seeds` is a closed map `{KEY: non-empty string}` (identifiers only, no braces in values); an explicit `"seeds": null` counts as ABSENT — nothing is seeded and unbound `{run.KEY}` tokens still refuse fail-closed that substitutes `{run.KEY}` inside the included subtree ONLY — an unbound `{run.KEY}` there is the existing fail-closed refusal, worded to name the alias. For an inline parent, binding scope is asymmetric by design: `run_context` map mode renders the pre-include fields only (goal/context/question/profile and the fan-out goals), so a `{run.KEY}` inside an included gate's `options[]` or `wait.until_argv[]` binds ONLY through that include's `seeds` — an unbound one there refuses fail-closed rather than shipping a literal button label or argv element. `exports` optionally maps inner node ids to public names the parent may reference; without it the parent may still name `alias__<id>` literally.

Namespacing is deterministic: every included node id becomes `alias__<inner-id>` (double underscore), length-checked against the 64-char id cap — on overflow or a dot the include is REFUSED, never truncated. The pass rewrites all six id-ref surfaces inside the included subtree in one shot: `after`, `inputs` heads, `requires` keys, `fanout.items_from` heads (together with their `after` entry IN LOCKSTEP — the items_from source must remain a direct `after` parent), `fanout.ledger` source heads (#85 — each row's `'<node_id>.<dotted.path>'` ref, string rows and `{source,...}` objects alike), and `when` `out.<id>.` paths (heads are not existence-checked at validate time, so the pass checks them itself). The parent may touch an included graph only through a namespaced name or an exported public name — a bare inner id, or the bare alias, is refused.

Guards, all refusals with the standard `errors:[{node, field, msg}]` envelope naming `include:<alias>` before any write or spawn: unknown/missing library entry, an included graph that fails to parse or validate standalone, alias collisions (two includes sharing an alias, or `alias__id` shadowing a parent id or another namespace), cycles across includes, a nesting-depth cap of 4, and merged node-count/size caps — the caps are checked per include against the growing candidate AND once more against the FINAL fused graph after the parent-ref rewrite, so the bytes that actually get committed are the bytes measured. An included graph's top-level `model_policy.forbidden_models` is a shelved safety floor: it UNIONs into the parent's `model_policy` (created when the parent has none; set semantics, deterministic sorted order) with an `include_note` naming the alias — including a graph must never relax what it forbids. Likewise `require_model` is a floor: a child asserting it ORs into the composite (a child `False` never relaxes a parent's `True`), noted loudly. No other child top-level key is carried (`defaults` never applies across the boundary; that asymmetry is itself noted). Non-fatal resolver warnings — e.g. a fixed absolute scratch path shared between an included graph and the parent — do NOT rewrite anything; they echo as `include_notes` on the run response and every status read, and the run is expected to be single-instance or materialized around the collision.

Strip-on-expand is the storage contract: the committed `graph.json` is the EXPANDED, include-STRIPPED truth, so amendments edit the expanded form (amending an already-expanded run is an identity no-op — no `include` key means nothing to expand). An amend that DOES carry a fresh author form (with `include`) re-expands and restamps `run.json`'s `includes`/`include_notes` for the new graph — provenance never describes a graph the run no longer carries. `save` is the one storage exception: a shelved composite stores the AUTHOR form (include key intact) so the shelf keeps tracking shelf updates — resolution stays at run time — while `save` still runs the resolver once purely to validate the guards. Because a composite RUN's `graph.json` is expanded-and-stripped, `save(run_id=...)` REFUSES when that run's `run.json` carries `includes`: shelving the expanded form would freeze one expansion of the shelf. Save the author graph inline (`save(graph=…)` / `save(graph_path=…)` with the `include` annotation) instead. Fingerprint economics ride the expansion untouched: parent nodes not wired to an include stay byte-identical (stable efp, replay-skip holds); editing an included library graph and re-running `from=` moves exactly the included defs' fingerprints, so precisely those lanes re-run.

Every expanded run records provenance: `run.json.includes = [{alias, name, source_digest}]` — which shelf's NODE CONTENT it ran with (declaration order; nested includes alias under their parents). `source_digest` keeps its existing contract: sha256 over the canonical `nodes` list ONLY — it pins the shelf's node bytes and nothing else, so an edit confined to include directives, seed values, or model_policy does NOT move the digest. Read it as 'which nodes ran', not 'which whole author file ran'. Like `provenance`, the `include` key is annotation: `def_hash`, `efp`, `graph_fingerprint` and `source_digest` of a graph without includes are unchanged, and golden-solo stays an empty diff.

## File-authored graphs

Use `graph_path` with run/save/amend/validate for a caller-authorized absolute local regular UTF-8 JSON file, at most 1 MiB, no final symlink. Choose exactly one source: inline graph, graph_path, or run's `from` / save's `run_id`. Validation completes before writing or spawning. Save to the library and replay with `from` for repeated use; graph_path is valuable for an unsaved local graph or replacement amendment. Neither feature asserts a universal tool-argument length limit.

A shared file may state its dialect with a top-level `grammar` key (`"wf/1"`; absent = `wf/1` for every pre-#32 file). A value this reader does not support is refused before any write or spawn, with the supported list in the error. Like `provenance`, `grammar` is a top-level annotation — never part of a node, so `def_hash`, `efp`, `graph_fingerprint` and `source_digest` are unchanged by it. The publishing convention (`<name>.workflow.json`, provenance, pinned digests, the no-code note) is [portable](portable.md).
